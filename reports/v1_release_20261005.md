# Local dashboard verification

## October 5, 2026 release

Implementation is in place and the local backend launches on GTX 1650 CUDA.
**Full browser acceptance is not established for this changed release.** Browser
file upload lost its session; native browser automation then refused further
interaction because it could not identify the current URL reliably. No bypass
was attempted. Mock DOM results below are not substituted for browser success.

## Changes

- Existing predictor/runtime/backend/frontend updated for hash verification,
  typed finite configuration, deliberate null-statistics normalization support,
  request deadlines, cancellation/generation safety, wall-clock freshness,
  local Pause/failure behavior and non-autoplay recovery.
- Current count/attention/overlay clear on stale/unavailable/error; graph remains
  explicitly historical. Paused-seek snapshots also expire. Raw signed float64
  counts, ImageNet preprocessing and preserved epoch-16 weights stay unchanged.
- CSV/JSON client-side export remains available disconnected; full precision,
  current segment only, timings/shapes, exact model provenance, original/playback
  metadata, conversion/padding/audio policy and bounded-history loss are recorded.
- Model-forward/service/client-latency/completed-rate/age metrics labelled
  separately; configurable attention reason explains threshold. Negative raw
  count is retained, but attention becomes unavailable rather than NORMAL.
- New checked Windows launcher and model manifest. Logs/errors remain visible;
  one worker, no reload, installs, downloads or training. Readiness before browser
  opening; matching ready service reused; port conflict errors tested.
- Footage now entirely Git-ignored, including videos/video1.mp4. Original media,
  dataset, weights, annotations and evaluation outputs not modified/deleted.

## Remaining acceptance and limits

- Stop-backend recovery without reload, browser CSV download and a 15-minute
  browser playback soak still need manual verification. The backend soak
  measured service behavior. Browser responsiveness and memory remain open.
- One shared session, no authentication/session isolation. Keep loopback only.
  Multipart upload limit is after parsing; no duration/conversion/disk quota or
  hardened media sandbox. Do not expose to LAN/internet or tunnel publicly.
- GPU/CPU performance varies; CPU may be too slow. Lossy playback conversion and
  JPEG browser samples are not pixel-identical to offline inference. Full-scene
  resize changes image scale and potentially count error. Heatmap is not people/m².
- Prototype attention thresholds are not validated safety limits. Mall/short HT21
  do not establish target-camera festival reliability; no correction multiplier.
- Forced process kill can leave owned temporary copies. No artifact license or
  media permission is invented. Fresh checkout requires trusted model separately.

See [benchmarking](../docs/benchmarking.md) for the target-camera and dense-scene
evaluation plan.
